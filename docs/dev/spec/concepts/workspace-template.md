# Workspace templates

## Purpose

Define how workspace templates are stored and validated before `ws create`.

## Location

- Templates are root-local:
  - `<current-root>/templates/<name>/`
- `<name>` validation follows workspace ID rules (`gion`-compatible; no path separators).

## Copy model

- `ws create` copies template content from `templates/<name>/` to `workspaces/<id>/`.
- Copy is static (no variable interpolation / placeholder expansion).
- `.kra.meta.json` is not template-managed; it is always generated by system.

## Reserved paths (top-level only)

The following paths are forbidden at template root (`templates/<name>/`):

- `repos/`
- `.git/`
- `.kra.meta.json`

If any reserved path exists, validation fails.

## Default scaffold

Generated default templates include:

- `notes/`
- `artifacts/`
- `AGENTS.md`
- `CLAUDE.md`
- `workspace.md`

The generated scaffold does not include `.cmux/dock.json`. A user-authored template may still contain
that file; validation accepts it and static copy preserves it unchanged, but kra does not generate or
manage its contents. `workspace.md` remains the workspace current-state and task source of truth at
`<workspace>/workspace.md`.

## Entry constraints

- Symlinks are forbidden.
- Unsupported special file types are forbidden.
- Validation reports all found violations in one run.

## Validation reuse

One shared validation implementation is used by:

- `kra ws create` (preflight before any workspace directory creation)
- `kra template validate`
